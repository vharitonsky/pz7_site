Практична 7 — персональне завдання

Автоматизований та AI-асистований пошук вразливостей. Введіть свій user-id зі списку групи, виконайте завдання прямо на сторінці та завантажте відповіді у файл для здачі.

Що і як робити

Інструкція однакова для всіх. Персональні дані з'являться нижче після вводу user-id. Живого сервера немає — усе робиться міркуванням по даних.

  1. Тріаж звіту DAST. Звіт — це список підозр сканера. Для кожної знахідки позначте Справжня (TP) чи Хибна (FP).
    FP — коли вразливість неможлива на цьому ендпоінті (нема параметра, куди інжектити; або нема дії/зміни стану), чи confidence = Tentative. Звіряйте знахідку з картою застосунку нижче.
  2. False negative. У карті застосунку позначте ендпоінти, що мають реальну вразливість, якої НЕМА у звіті — сканер їх проґавив (FN — найгірший випадок: тихо пропущена діра).
  3. AI-код-рев'ю. Для кожного фрагмента визначте клас вразливості (можна за допомогою AI — Gemini / ChatGPT / Claude, без підказки класу) і впишіть його в поле.
  4. Обхід payload-а. За заданим фільтром напишіть у поле змінений payload, що обходить фільтр, і коротко поясніть механізм — чому саме цей варіант фільтр не ріже.
  5. Здача. Натисніть «Завантажити відповіді (JSON)» і прикріпіть файл у Moodle-завдання. Самоперевірки тут немає — оцінює викладач.

Приклад (на сторонніх даних — не з вашого варіанту)

Тріаж: SQL injection — /news (Firm). На /news нема вхідного параметра → інжектити нема куди → Хибна (FP).
False negative: у карті є /upload — «приймає файл без перевірки типу», але у звіті його немає → це пропущена вразливість (FN), позначаємо.
Код-рев'ю, приклад фрагмента (іншого класу, ніж у вашому наборі): 
app.get('/go', (req, res) => {    // ендпоінт переходу
  res.redirect(req.query.url);     // url не перевіряється
});
Промпт до AI: «Назви клас, вразливий рядок, механізм і payload. Не вигадуй зайвого.» Клас: Open redirect.
